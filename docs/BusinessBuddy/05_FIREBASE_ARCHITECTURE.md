# Purpose

This document defines the Firebase architecture used by Business Buddy.

The goal is to create a backend that is secure, scalable, maintainable and easy for AI developers to understand.

The frontend must never communicate directly with Firestore without passing through the application's service architecture.

---

↓

↓
Repositories

Business Services

---

# Responsibilities

UI Layer

Responsible for:

Displaying information
Receiving user input
Showing loading states
Showing success messages
Showing validation errors

The UI must never perform business calculations.
The UI must never calculate invoice totals.
The UI must never calculate tax.

---

Repository Layer

Responsible for:

Reading Firestore
Writing Firestore
Listening for realtime updates
Offline cache
Retry logic

Repositories never contain business rules.
Repositories only move data.

---

Business Service Layer

Responsible for:

Invoice calculations
Tax calculations
Validation
Business rules
Status transitions
Financial integrity
Invoice numbering

This layer contains the application's intelligence.

---

Firebase Layer

Responsible for:

Authentication
Storage
Realtime database updates
Offline persistence
Cloud messaging
Cloud functions

Nothing else.

Each authenticated user receives
UID

Each user belongs to
One Business

Rules

Unauthenticated users cannot access data.
Users only access their own business.
Email verification required.
Sessions automatically restored.

Roles supported in architecture (Version 1 uses Owner only):
* Owner — full access
* Manager — almost full access (future)
* Employee — create jobs/customers; no financial reports or settings (future)

# Security Philosophy

Never trust the client.
Never trust calculated totals.
Never trust invoice numbers.
Never trust permissions.

Everything validated on trusted backend before becoming permanent.

---

# AI Developer Rules

The AI must never:

Write directly from UI to Firestore.
Generate invoice numbers locally.
Trust user-entered totals.
Skip validation.
Ignore permission checks.
Duplicate repository logic.
Hardcode Firestore paths.
Bypass service layer.

Every Firebase interaction must pass through the documented architecture.

---

# Guiding Principle

Firebase is a storage and synchronization platform.

Business Buddy's intelligence lives inside the Business Service Layer.

Firestore stores data.
The Service Layer decides whether that data is valid.
